# 投稿渠道与经验总览

Submit 的数据仍以 `submit-preview/data/venues.json` 为单一来源，共用主站与独立预览。总览只增加阅读参考，不覆盖届次、截止日期、模板或经验原始记录。

## 渠道总览

原有数据封套保持版本 1，新增 `venue_profiles`，独立使用版本 1。旧封套可在兼容模式下读取；发布构建要求每个可见渠道恰有一份完整总览。预印本服务与仅用于历史发表识别的渠道不加入当前推荐列表。

- `venue_id` 连接已有渠道
- `teaser` 与 `teaser_source_ids` 为列表中的短摘要及依据
- `sections` 包括定位、主题、贡献风格、机器人相关性、出版形式与理解边界，每节均有官方或第一手来源
- `evidence_kind` 区分原始资料转述与编辑归纳；论文风格必须标为编辑归纳
- `checked_at` 是本次总览核读日期，`reference_years` 是使用资料的年份，两者不代表本届投稿状态
- 来源复用顶层 `sources`，保留标题、URL、资料年份、核对日期、读取范围与访问状态，并保留官方来源、作者项目页或登记资料各自的身份

每节的“依据”可展开引用列表。论文录用、会议展示、期刊出版、Workshop 与主会不混为同一种身份；文章示例只能说明可能的贡献类型，不是接收标准或录用难度排名。

## 经验阅读

`experiences.overview` 是版本 1 的编辑摘要层，按 `record_id` 连接每条来源。列表展示原有正文摘要、精简的可借鉴点与结果/边界，完整页保留方法、来源背景、核读范围、评论与局限。原作者自述与评论者后续结果保持分开。

全局摘要与六条跨来源归纳默认可见。归纳的来源链接进入站内完整整理；外部原文是次级入口。列表筛选、详情返回、浏览器前进后退与来源独立计数继续使用同一套 URL 状态。

## 来源覆盖与使用边界

当前共 14 条来源记录：原有 7 条，加上 IJRR、JFR、CoRL、RSS、ICRA/IROS 的 6 条经验和 1 条明确区分主会的 RSS TaskSpec 工作坊转投案例。每条都有独立摘要和阅读边界；来源记录数不等于独立作者、论文或成功样本数。跨帖同账号、同帖不同评论者、匿名评价以及年份未知均保留限定，不能用于录用概率或平均审稿周期计算。

完整整理中的 `timeline` 仅呈现作者自报的状态节点，不把状态日改写为提交日；`cases` 保留同页的不同投稿记录；`supporting_sources` 和评论链接提供后续更新或独立名单核对的具体依据。新增记录的做法明确标为编辑启发，不声称原作者已经采用或验证有效。工作坊身份同时写入标题、摘要与结果边界。

T-RO 的完整新投稿时间线仍缺少可用证据。

## 验证

`submission_profiles.py` 校验覆盖率、版本、字段白名单、来源引用、日期、公开 HTTPS URL 与证据类型；发布生成器在写出页面前执行检查。相关 Python/JavaScript 测试覆盖完整性、转义、数据兼容模式、列表/完整阅读、证据展开、筛选返回与原有日期冲突边界。浏览器视觉验证与静态检查分别记录，不能相互替代。

主站与独立预览的构建入口同时携带脚本和数据的内容哈希。经验数据初载与重试使用同一个带数据版本的 URL；即使只更新 JSON 而不改脚本，新页面也不会复用上一版数据缓存。原始数据与脚本字节不因入口版本参数而改变。
