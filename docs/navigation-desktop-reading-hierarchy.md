# Desktop reading hierarchy

This candidate reorganizes the navigation reading shell at desktop widths (the acceptance viewports are 1440×900 and 1920×1080). It does not change scientific data, route fields, original parentage, source identity or version isolation. Real browser acceptance is separate from static/JSDOM tests.

## Reading states

- The default field overview keeps every current main task and original global challenge entry. All original parent paths remain. Non-tree relations are selected on demand, with an explicit show-all control and complete source evidence. The evidence panel has its own temporary reading position, restored with its selected relation.
- A task opens its original single active L or C forest. The relation picker is in the toolbar, outside the tree scroll flow. Selecting it does not move the tree. The right pane keeps the actual object title and exact evidence version outside its scrolling body. Task context and full original ancestry are available on demand without repeating the task definition above each selected relation.
- A method's fixed heading exposes this exact version's analysis status. The primary entry uses the first real `analysis_answer` in original traversal order. The separate full-structure entry and old root deep links show the original-root coverage summary. Existing unfilled template nodes and paper-specific instances remain in their original topology. An unimported version does not borrow another version's answers.

Counts are derived from current model records. Coverage is selected-section reading, not a claim of complete-paper review or independent reproduction. An imported analysis version with no corresponding local method position remains available through the explicit version library; no method placement is manufactured.

## Method-reading state

At desktop widths, an actual selected `pipeline_recipe` or `versioned_method_card` in g or L uses a 400px tree pane at1440 and448px at1920, with a16px gap and a primary992px/1424px reader pane. This is derived presentation state, not a new route field. S0, task inventory, selected relationships, C, A and narrow layouts keep their own geometry.

The method tree now shows the exact source ancestor chain, selected method and normally expanded original children. It does not substitute a local L placement for a g method, or combine same-paper versions. The title is “当前位置与来路”. Other real-parent children remain explicit native navigation controls outside the ARIA tree, in their original order, with full source labels, roles and version warnings. They are not a new scientific group or an inheritance claim. Displaying the path does not rewrite persisted expansion buckets. Right-arrow follows the actual rendered child in this path, and all tree levels/parent IDs remain original.

The fixed method heading retains the complete existing object label, full source version and snapshot warning. Analysis status and existing actions share a compact row. The measured VLFM acceptance target is a heading no taller than128px and body starting byy261; there is no clipping, ellipsis, line clamp or hard height cap to force long source identity through. Original source warnings take priority if a real case cannot meet that target. The method body no longer visibly repeats the role/parent/direct-branch interface introduction; the full mechanism, conditions, boundaries and evidence remain. All genuine A answers are unchanged.

Method navigation is a natural-flow tree rather than the absolute-positioned overview map. It does not carry legacy map geometry attributes, which would otherwise activate old high-priority card and truncation styles. The two permanent scrolling regions remain the same. Entering a method saves the previous effective layout offsets before narrowing; returning restores the exact original task/relation route, selected relationship, scroll, focus and origin. Reader collapse/reopen preserves actual DOM identity.

## Display migration and unchanged state contracts

The ready desktop document has no outer-page scrolling. `#np-tree-scroll` and `#np-detail-scroll` are the two permanent reading scrollers. The latter is now a child of the stationary `.np-reading-pane`; its title is a fixed sibling. The inner evidence `.np-detail-scroll` remains natural flow.

An old saved outer-page offset displays as zero in ready desktop mode. Capture records zero for the active page offset. This does not clear old history, other context buckets, origin snapshots, effective tree/reader offsets, focus, expansion, zoom or the independent L/C task views. Same-hash relation history entries remain distinct. Narrow-width legacy offset behavior is unchanged.

On desktop, generated copies of the selected object identity in the summary share its fixed heading only when the active route and heading match the exact position, entity, paper and version. A raw `plain_language_question` that exactly equals the complete fixed title is represented there once with the explicit “研究问题” field role. Different questions, punctuation, qualifiers, source/version notes, scope boundaries and all actual A answers remain. The original source field and evidence body are retained. Narrow layouts keep the original summary headings and question block. Optional peer context wraps within the existing pane on desktop; it does not create another scrolling strip. Screenshot scroll enumeration respects closed disclosure ancestors while still rejecting a genuinely visible third scroll region.

Toolbar disclosures and supporting sheets are temporary. Closing a sheet restores its actual trigger, including Escape. Full original ancestry labels wrap in an on-demand path disclosure rather than being truncated into a compact scientific label.
